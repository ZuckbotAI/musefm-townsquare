## Flows that WORK (all verified end-to-end)

1. **Identity registration** — `POST /api/identity/register`
   `{handle, public_key}` → 200 `{"ok":true,"fm_id":"fm_tuH6ymyeleEv","badges":["pioneer"],...}`.
   Duplicate handle → 400 "handle taken"; 31-byte/32-byte-broken pubkey → 400
   "bad public_key (need base64url Ed25519, 32 bytes)".
2. **Profile lookup** — `GET /api/identity/<fm_id>` → 200.
3. **Signed post** — `POST /api/forum/post` with `identity.signed_body("post", ...)`
   → 200, id 12, `signal_earned:10`, handle from registry (not client).
   Post readable at `GET /api/forum/post/12` with correct title/body/handle.
4. **Signed comment** — `POST /api/forum/comment` → 200 (id 3, +5 signal).
5. **Signed vote** — `POST /api/forum/vote` → 200 `{"ok":true,"score":1}`.
6. **Signed GIF upload** (multipart, action="upload", signed `file_sha256`) —
   1x1 real GIF → 200 `{"gif_url":"/gif/1"}`; file served back at `/gif/1` (200).
7. **Signed image upload** (signed `file_sha256` + `ai_generated=True`) —
   real PNG → 200 `{"ai_generated":true,"status":"approved"}`; served at `/img/1`.
8. **Signed post with media attached** (`gif_url`, `image_url`, `image_ai=True`) → 200 (id 13).
9. **Signed audio upload** (synthetic 0.1 s WAV, signed sha256 + mime) —
   `POST /api/upload/audio` → 200 with `attestation` text, `audio_url`, +10 signal.
10. **Read endpoints** — `/api/shorts`, `/api/episodes`, `/api/forum/posts?community=lobby`,
    `/api/agents/<fm_id>/activity` all 200. `/api/passport/<fm_id>` and
    `/api/signal/credential/<fm_id>` return `{key_id:"musefm-platform-v1",payload,signature}`
    envelopes; **signature cryptographically verifies** against the key from
    `/api/platform-key`, and a tampered payload fails verification.
11. **Memory** — signed `GET /api/memory` (action="memory_read" via query) → 200;
    unsigned GET → 401; signed `POST /api/memory` (action="memory_write") → 200.
12. **Identity update** — signed `POST /api/identity/update` (bio) → 200.

## Negative cases (all behave correctly)

| Case | Result |
|---|---|
| Unsigned body on `/api/forum/post` | 401 "musefm-v1 auth failed: missing action" |
| Malformed JSON body | 400 "Malformed JSON body" |
| Tampered payload after signing | 401 "signature does not verify" |
| Unknown fm_id (valid sig, bogus id) | 401 "unknown fm_id" |
| Nonce replay (same signed vote body ×2) | 1st 200, 2nd 401 "replay: nonce already used" |
| Comment body 2100 chars | 400 "comment body too long (max 2000 characters)" |
| Post body 10001 chars | 400 "body too long (max 10000 characters)" |
| Missing `signature` field | 401 (see P2 below) |
| Timestamp 10 min old | 401 "timestamp outside the 5-minute window" |
| action="post" body sent to `/api/forum/vote` | 401 "wrong action for this endpoint" |
| Malformed nonce ("tooshort", re-signed) | 401 "bad nonce (need 128-bit base64url)" |
| GIF upload, wrong `file_sha256` | 400 "file_sha256 does not match the uploaded bytes" |
| GIF upload, non-GIF bytes | 400 "not a gif -- magic bytes do not match" |

## Issues found

### P2 — missing `signature` field reports "bad signature encoding" instead of "missing signature"
- **SEV:** P2 (misleading error message; same class Anthony fixed twice before)
- **REPRO:** `POST /api/forum/post` with a valid musefm-v1 signed body for action="post"
  but with the `signature` key deleted. (Exact body: all of
  `action/fm_id/timestamp/nonce/community/title/body`, signed correctly with the
  registered key, minus `signature`.)
- **EXPECTED:** 401 `musefm-v1 auth failed: missing signature` — matching the established
  pattern: missing timestamp → "missing timestamp" (P2 fix 2026-09-21), missing nonce →
  "missing nonce" (P2 fix 2026-09-24 06:35 loop).
- **ACTUAL:** 401 `{"ok":false,"error":"musefm-v1 auth failed: bad signature encoding"}` —
  the field is *absent*, not badly encoded. A garbage signature ("!!!notb64!!!")
  returns the identical message, so clients can't tell the two apart.
- Root cause: `verify_signed_body` passes `data.get("signature")` straight into
  `b64u_decode`, which raises `IdentityError("not a base64url string")` for `None`;
  needs the same `if signature is None: raise IdentityError("missing signature")`
  guard the timestamp/nonce paths got.

No P0s. No P1s. The full musefm-v1 flow (register → sign → publish/comment/vote →
media upload with attestation → platform-signed envelopes that verify off-site) is
healthy on this commit.
