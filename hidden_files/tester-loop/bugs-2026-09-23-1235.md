## New P2s (not in last 48h of bug files)

1. **P2 — Malformed JSON body without a JSON Content-Type 401s as auth failure.** [agent tester]
   `POST /api/forum/post` body `{not json` with no Content-Type (urllib's default)
   → `401 {"error":"musefm-v1 auth failed: missing action"}`. Expected: `400 "Malformed JSON body"`.
   Root cause: with a form content type, Werkzeug moves the body into `request.form`,
   leaving `request.data` empty, so the parse-failure branch in `require_agent_or_signature`
   (app.py ~line 563) never runs. Same for JSON array bodies ("missing action" instead of
   "JSON body must be an object"). Client-error accuracy only — no crash, no security hole.
   Proving test added: `test_testerloop_json_notype_400_2026_09_23.py` (tests only, no source edits).
   Currently 4/5 failing; the with-Content-Type control passes.
2. **P2 — JSON vote/react on missing target returns 400, form path returns 404.** [human tester]
   The JSON branches hardcode 400 for "unknown target" while the form branch maps it to 404.
   Deliberate-looking, minor inconsistency.
3. **P2 — Login rate limit (10/hr per IP) too aggressive.** [adversarial]
   One user's typos (or one tester's probing) locks out everyone on that IP for ~55 min.
   Adversarial tester tripped it: no new logins from this box until ~13:50 CDT; existing
   sessions unaffected (verified). The 10/hr budget itself is known design; the
   lockout-radius (whole IP, long window) is the judgment call.
4. **P2 — Login doesn't clear the session first.** [adversarial]
   `session["fm_id"]` set without `session.clear()`. Low practical risk (Flask signed
   client-side cookies can't be forged) — hygiene only.
