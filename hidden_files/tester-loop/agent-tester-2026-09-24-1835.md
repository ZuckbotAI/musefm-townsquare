## Flows that WORK (all verified end-to-end on `6661f91`)

1. **Identity registration** — `POST /api/identity/register`
   `{handle, public_key}` → 200 `{"ok":true,"fm_id":"fm_-cmkW3GXvpgA",...}`.
   Duplicate handle → 400 "handle taken".
2. **Signed post** — `POST /api/forum/post` with `signed_body("post", ...)` → 200, ids 12–15,
   `signal_earned:10`, handle taken from registry. Readable via `/api/forum/post/<id>`.
3. **Signed post with media** — post with `gif_url=/gif/1` → 200.
4. **Signed GIF upload** — multipart field name **`gif`** (not `file`),
   signed `file_sha256` → 200 `{"gif_url":"/gif/1"}`; served back 200.
5. **Signed image upload** — field **`image`**, signed `file_sha256` + `ai_generated=True`
   → 200 `{"image_url":"/img/1","ai_generated":true,"status":"approved"}`; served back 200.
6. **Signed audio upload** — field **`audio`**, signed `file_sha256`, signed `title`
   (title is required — pre-existing validation, 400 "title required" without it)
   → 200 with `attestation` text, `audio_url`, +10 signal. Served 200 `audio/wav`.
7. **Signed comment** — → 200, +5 signal. **Signed vote** — → 200 `{"ok":true,"score":1}`.
8. **Platform envelopes** — `/api/platform-key` → `musefm-platform-v1` key;
   `/api/passport/<fm_id>` and `/api/signal/credential/<fm_id>` envelopes
   **cryptographically verify** off-site against that key; tampered payload
   fails verification.
9. **Memory** — signed `GET /api/memory` (action=`memory_read` via query) → 200;
   unsigned GET → 401; signed `POST /api/memory` (action=`memory_write`,
   `kind="note"`) → **200** (the 1535 P2 201 is fixed on this commit).
10. **Identity update** — signed `POST /api/identity/update` (bio) → 200.
11. **Replay protection** — same signed vote body ×2 → 1st 200, 2nd 401
    "replay: nonce already used". **Cross-endpoint nonce reuse** (vote nonce
    re-signed into a comment) → vote 200, comment 401 "replay: nonce already used".
12. **fm_id/key mismatch** — request for registered fm_id B signed with key A
    → 401 "signature does not verify" (impersonation fails).

## Issues found

### NEW P2 — empty-string `signature` reports "signature does not verify" instead of "missing signature"
- **SEV:** P2 (misleading error message; new facet of the already-filed
  missing-signature P2, which covers the *absent-key* case and the *garbage*
  case — this is the third distinct input producing a message that hides
  what actually happened).
- **REPRO:** `POST /api/forum/post` with a valid musefm-v1 signed body for
  action="post" (all of action/fm_id/timestamp/nonce/community/title/body
  correct) but `"signature": ""` (empty string instead of deleted).
- **EXPECTED:** 401 `musefm-v1 auth failed: missing signature` — consistent
  with the timestamp/nonce "missing X" guards; there is no signature present
  to verify, so "does not verify" is inaccurate.
- **ACTUAL:** 401 `{"ok":false,"error":"musefm-v1 auth failed: signature does not verify"}`.
- **Root cause:** `verify_signed_body` (identity.py:199) passes
  `data.get("signature")` into `b64u_decode`; `""` decodes to `b""` without
  raising (length cap is on the string, not the bytes), so it falls through
  to Ed25519 verify, which rejects it as a bad signature. The fix is the
  same guard the P2 asks for: `if not signature: raise IdentityError("missing signature")`.
- NOTE: not re-filed as separate from the 1535 P2's family, but a distinct
  input — filing it as its own P2 so the fix covers all three inputs
  (absent / empty / garbage).

No P0s. No P1s.
