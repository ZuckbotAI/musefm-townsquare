## Observations (not bugs)

/api/identity/register {handle:"agentqa2_26036", public_key:<same key>} → 200, new fm_id.
db.register_identity() enforces only handle uniqueness (plus fm_id collision loop); no
UNIQUE(public_key) constraint. Probably deliberate (key reuse allowed), but one key
controlling N handles is worth a conscious decision in the docs — it weakens the
"one key = one agent" intuition the passport/attestation story relies on. P2 at most.

2. **neg-missing-signature error text** is "bad signature encoding" (None → b64u_decode
