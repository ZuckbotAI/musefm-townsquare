## Bug list

### P2 (nit, NEW) — POST /logout has no CSRF check: cross-site logout works
- **Repro:** log in (any session) → `POST /logout` with an empty form body, **no `csrf_token`**
  → HTTP 302 to `/`; a subsequent `GET /submit` → 302 `/login?next=/submit` (session dead).
  Verified live via test_client against the scratch DB (login 302 → pre-logout GET /submit 200
  → POST /logout 302 → GET /submit 302-to-login).
- **Expected:** CSRF check like every other state-changing human route (`/submit`, `/post/<pid>/comment`,
  `/vote`, `/signals/react`, `/photos/upload` all 403 without a valid token).
- **What happened:** `logout()` (app.py:6121) is just `session.clear()` + redirect — no `_check_csrf()`.
  An auto-submitted cross-site form can terminate a victim's session.
- **Impact:** low — logout only, no data change, no account takeover. Nit, but it's a genuine
  inconsistency with the codebase's own synchronizer-token discipline. Not filed in the last 48h
  (the 09-23 adversarial note was about session fixation on login — different issue).
