## BUGS FOUND

### [P1] POST /vote with missing `value` param silently records an upvote
- Root cause: app.py:1462 `value = _int_field(data, "value", 1)` — missing/empty `value`
  falls back to default 1 (upvote) instead of 400.
- Repro (logged in, valid CSRF):
  1. POST /vote with target_type=post, target_id=8, value=-1 -> vote is -1 (DB verified).
  2. POST /vote with target_type=post, target_id=8 and NO value param -> HTTP 302,
     DB vote flipped from -1 to +1.
- Also: voting `value=""` (empty) behaves the same -> +1, and since db.vote() toggles
  off same-direction votes, it DELETED an existing +1 vote (row removed).
- Expected: 400 "value required" for missing/empty, like other bad inputs.
- Note the code even has a comment (P2 2026-09-20 00:46) saying bad vote input should
  surface errors rather than act silently; this case slipped through the default.
