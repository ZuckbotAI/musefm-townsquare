## Methodology note (harness, not app)
- Early in this run, POSTs returned 403 "bad form token" even with a freshly-fetched token. Root cause was MY harness: I wasn't saving updated Set-Cookie between requests, so the session cookie I sent predated the csrf_token issuance (Flask session cookie changes when the token is first stored). With `-b jar -c jar` on every request, tokens work correctly — the app's CSRF is fine. The 403-page token rotates per render because each unauthenticated-by-cookie GET mints a fresh token; not an app bug.
