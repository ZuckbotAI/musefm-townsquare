## P1 — NEW (live-demonstrated + code-confirmed): unauthenticated junk burns rate budgets before validation
- Found by: adversarial QA. REPRODUCED LIVE + CODE-CONFIRMED by run lead.
- What: `POST /api/workroom/create` (signed flow) calls `check_limit("wr_api", 30)`
  BEFORE parsing JSON or verifying the signature (app.py:7533-7539). 30 junk
  POSTs (`{"junk":1}`) each return 401 yet each consumes one budget slot, so a
  subsequent LEGITIMATE signed workroom_create gets
  `429 {"error":"rate limit hit — slow down, friend"}` — workroom creation is
  DoS'd for an hour, per IP. Self-DoS per IP, but on shared egress/NAT one bad
  actor locks out everyone behind it.
- Repro (exact, local instance):
  ```
  for i in $(seq 1 35); do curl -s -X POST -H "Content-Type: application/json" \
    -d '{"junk":1}' http://127.0.0.1:8473/api/workroom/create; done
  # then a valid signed workroom_create → 429
  ```
- Same ordering issue, code-confirmed on two more routes:
  - `/api/upload/gif` (app.py:5495): `check_limit("gif_upload", 10)` before
    `verify_signed_body`.
  - `POST /api/asks` (app.py:6413): `check_limit("ask_post", 5)` before
    `_asks_asker` auth. (Not live-demoed — burning the 5/hr budget would have
    locked out the parallel testers.)
- Expected: malformed/unauthenticated requests 400/401 WITHOUT consuming the
  rate budget — matching the codebase's OWN documented rule (P2 2026-09-19
  comments on `/api/identity/register` and `/api/forum/post`: "Validate BEFORE
  counting the rate budget"). The rule exists; these three routes predate or
  missed the fix.
- Suggested fix (no source edited per policy): move `check_limit` after
  `json_body()`/`verify_signed_body`/`_asks_asker` on these routes.
- Failing regression test added (tests only, no source changed):
  `test_testerloop_ratelimit_before_validate_2026_09_20.py` — currently
  3 pass / 2 FAIL (valid signed create returns 429 after 30 junk POSTs).
- Dedupe: not in any bug file from the last 48h. Distinct from the 1535 P1
  (X-Forwarded-For rotation — a different mechanism) and from the 1835
  shared-IP "post" bucket note.
