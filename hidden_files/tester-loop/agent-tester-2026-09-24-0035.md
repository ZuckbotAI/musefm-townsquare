## 4. Caveats / not-a-bug observations

- 4 checks could not be live-verified because the per-IP `post` rate bucket
  (5/hr) was exhausted — this server is shared with the HUMAN and
  ADVERSARIAL testers on the same loopback IP, and my two successful posts
  + their traffic filled it:
  - empty body on signed endpoint (expected 401 "missing action") → 429
  - post unknown community (expected 400) → 429
  - post missing title (expected 400) → 429
  - post 500-char title (expected 400) → 429
  The code paths are the same validate-before-limit structure as the comment
  route, whose 400s DID verify live ("unknown post", "comment body required"),
  and the raise sites were read directly in app.py. Not a code defect; the
  429-before-parse ordering on empty bodies matches the documented design
  (rate peek before nonce burn).
- Empty-body probes: `curl`-style empty POST with no Content-Type also hit
  429 for the same reason; the "missing action" 401 for a truly empty signed
  body is per code path `data = data or {}` → verify raises "missing action".
- No external network was touched by posting: `tb.mirror_work` only fires
  when a Trustline profile is linked (our test identity linked none).
- `note_nonce` replay store is in-memory in this process; replay rejection
  verified within a single server lifetime (correct per 24h window design).
