## Comments (/post/<pid>/comment)
- Normal comment → 302, comment visible on thread. OK
- 500-emoji body + weird URLs comment → 302. All 500 emojis render; dangerous schemes NOT linkified: 0× `href="javascript:`, 0× `href="ftp:`, 0× `href="data:`; `//evil.example/path` rendered as plain text; only `https://example.com/ok` became a link (`target="_blank"` + noopener). OK
- **BUG (P2): overlong comment silently truncated.** POST 2500-char body → 302 (no error). Stored comment length = 2000 (`db.clean()` truncates via `s[:limit]`; the route only checks truthiness, never rejects overlength). The user loses 500 chars with no warning. Inconsistent with /submit's own stated policy ("overlong titles … reject with 400 instead, matching the body behavior"). Repro: `curl -b cj.txt --data-urlencode csrf_token=… --data-urlencode "body@long.txt(2500×x)" http://127.0.0.1:8473/post/8/comment` → 302; `select length(body) from comments …` → 2000.
- Empty/whitespace-only body → 400 "comment body required". OK
- Double-submit identical comment (rapid, same body) → both 302 but only **1 row** stored — the `last_identical_comment` dedupe guard works. OK
- Comment on missing post (/post/99999/comment) → 404. OK
