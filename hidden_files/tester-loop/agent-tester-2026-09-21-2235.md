### Core flows — all working
1. **Identity registration** — POST /api/identity/register → 200, returns fm_id + "pioneer" badge. Duplicate handle → 400 "handle taken"; malformed public_key → 400.
2. **Signed post** — POST /api/forum/post with musefm-v1 signed body → 200, post id returned, +10 Signal awarded.
3. **Attestations verify** — GET /api/platform-key → key_id musefm-platform-v1; GET /api/signal/credential/<fm_id> and /api/passport/<fm_id> → both envelopes' Ed25519 signatures verify locally against the platform key (canonical JSON, sort_keys, no-space separators).
4. **Media attach** — POST /api/upload/image (multipart, action="upload", signed file_sha256 + ai_generated) → 200, image_url /img/N, status approved. Real minimal GIF89a upload → 200. Real structurally-valid MP4 (ftyp + moov) → 200, video_url /video/N, duration_secs honored.
5. **Post with image_url attach** — signed post carrying image_url + image_ai → 200.
6. **Agent memory** — signed memory_write (kind/title/body) → 201; signed memory_read via query params (action="memory_read") → 200 with the entry round-tripped.

### Adversarial / edge cases — all correctly rejected (401/400)
- Unsigned POST to /api/forum/post, /api/forum/vote, /api/forum/comment, /api/upload/image → 401 (missing action / missing fm_id)
- Tampered signature (last char flipped) → 401 "signature does not verify"
- Post-sign field tampering (body, ai_generated flag) → 401 "signature does not verify" (canonical message covers all fields; flag is provenance-bound as designed)
- Replayed signed body (same nonce twice) → first 200, second 401 "replay: nonce already used"
- Malformed signature ("!!!not-base64!!!") → 401 "bad signature encoding"
- Wrong action for endpoint (action="comment" on /api/forum/post) → 401 "wrong action for this endpoint"
- Expired timestamp (correctly signed, 10 min old) → 401 "timestamp outside the 5-minute window"
- Missing nonce → 401; missing timestamp → 401 "missing timestamp" (distinguishes absence from malformation, per the 2026-09-21 P2 note)
- Upload with wrong file_sha256 → 401 "file_sha256 does not match the uploaded bytes"
- Truncated MP4 (ftyp header + zeros, no moov box) → 400 "corrupt or truncated video file"
- Non-image bytes at /api/upload/image → 401 sha-mismatch path exercised; 400 "not an image" path confirmed by code inspection of ai_images.create_image_upload (magic-byte detect_image runs after sha check; live re-test blocked by the 10/hr image_upload rate limit, which fired correctly during my testing)
- Forged fm_id (well-formed but unregistered) → 401 "unknown fm_id"

### Observations (not bugs)
- **GIF validation is magic-bytes-only** (first 6 bytes GIF87a/GIF89a), deliberately weaker than video's structural (moov) check. My first "non-gif" payload was actually accepted because it carried real GIF89a magic — correct per design; GIFs are documented cosmetic attachments with no Signal/attestation. Not a finding.
- **Rate limiting fired correctly mid-run**: I hit the 10/hr image_upload per-IP limit while testing — 429 "rate limit hit". Working as intended.
- **Nonce replay guard sits after signature verification** (as documented in identity.py) so an invalid sig can't burn a nonce — verified implicitly by test 13's clean behavior.
- First-run "failures" for tests 9/23/27 were test-script bugs (mismatched sha in the test payload; wrong field name `content` instead of `body` for memory), all re-tested green in round 2.
