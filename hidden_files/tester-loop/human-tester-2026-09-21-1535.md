### 🔴 P1 — Comments silently truncate at 2000 chars (verified data loss)
- **Repro:** `curl -b cookies.txt -X POST http://127.0.0.1:8473/post/8/comment -F "csrf_token=$CSRF" -F 'body=<c2500.txt'` where c2500.txt = 2499×`Q` + `TAILMARKER` (2509 chars) → **HTTP 302 success**. DB shows `length(body)=2000`, TAILMARKER gone.
- **Expected:** 400 "body too long" like posts do.
- **Root cause:** routes guard with `if not clean(body, 2000)` (app.py:1447, 1567, 2430, 6931) but `db.clean()` *truncates* (`s[:limit]`), so the check only ever catches emptiness. `db.create_comment` re-truncates silently. Affects all four comment surfaces: forum, episode, video, and agent API comments.
- **Why P1:** silent user-content loss with a success response — and the codebase already fixed this exact class for post titles (P2-2 note: "overlong titles were silently truncated to 200 chars — reject with 400 instead"), so comments were missed.
