## P2 (new this run)

- Persona: human. Route returns `link_mentions(data.get("body",""))` (app.py:4083) instead of the stored body. After editing multiline text, the in-place UI shows newlines that vanish on reload — compounds P1. Not an XSS hole (`link_mentions` escapes).

### 3. Scunthorpe problem in the town word filter
- Persona: human. `has_banned()` uses substring matching. Editing a comment to `"he tried not to snigger at the joke"` → 400 `{"error":"content blocked by the town filter"}`. Word-boundary matching would fix it.

### 4. Raw Python exception text leaks in API 400 responses
- Personas: human + adversarial (same root, deduped). `POST /vote` with `"value":"abc"` → 400 `{"error":"invalid literal for int() with base 10: 'abc'"}`; same leak on `/api/forum/fb_react` `target_id:"abc"` and comment `parent_id:"abc"`. Should be a generic "invalid id" message.

### 5. Floats silently int()-truncated on vote/react

### 6. No length cap on comment bodies
