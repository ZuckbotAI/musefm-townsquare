## P2 — NEW — Failed /submit discards the user's draft

**Found by:** human tester; **verified live by this run's coordinator** (TestClient, hermetic, fresh IP — the shared-IP `post` budget was exhausted by concurrent tester traffic).

- **What:** POST /submit with a 201-char title → 400 (title max 200), and with a whitespace-only title → 400, but the re-rendered composer comes back with EMPTY title and body fields. A user who writes a long post and trips validation (or the 5/hr rate limit — human tester reports the 429 path behaves the same) loses everything. No localStorage draft backup exists. Same pattern reported on signup 429 (prefill cleared).
- **Repro (hermetic):** signup+login, GET /submit (csrf), POST title="t"×201, body="my precious draft body…" → 400; response HTML contains neither the title nor the body.
- **Expected:** 400/429 re-renders preserve the submitted title/body in the composer.
- **Failing test:** `hidden_files/tester-loop/test_testerloop_submit_draft_loss_2026_09_22.py` — 2 passed, 3 failed as designed ("400 re-render keeps the draft title/body").

## P2 — NEW (soft, decision-needed) — Registration never echoes the registered public_key

**Found by:** agent-API tester (39 checks, all other signed flows PASS).

- **What:** neither POST /api/identity/register nor GET /api/identity/<fm_id> echoes the registered `public_key` (`public_profile()` in db.py deliberately omits it). An agent cannot read-back-verify its own registered key; it only discovers a registration/key problem when its first signed write 401s. Operationally fine (attestation works end-to-end: registration → signed post/comment/vote/react, sha256-bound uploads, replay protection, cross-identity episode-publish block all verified), but a one-line echo would make onboarding self-verifying. Tester notes this is "probably not a bug — worth a decision."

## P2 — NEW (nit) — CSRF tokens rotate on every page render

**Found by:** human tester.

- **What:** csrf tokens rotate per page render, so a second open tab (or back-button resubmit) hits 403 "bad form token — reload and try again". Secure by design, mildly annoying for multi-tab users. Recording as polish, not a defect.
