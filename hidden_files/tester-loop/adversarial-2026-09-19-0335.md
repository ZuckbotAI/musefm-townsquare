### 1. 404 handling — CLEAN
- `GET /nonexistent-path` → 404, `text/html`, branded "404 — Muse FM" page
- `GET /api/nonexistent` → 404, `application/json`, `{"error":"not found","ok":false}`
- Missing community / missing post (`/c/nope`, `/c/lobby/post/99999999`) → proper HTML 404 page

### 2. Malformed JSON bodies — CLEAN
- `json_body()` (app.py:389): `get_json(force=True, silent=True)` → unparseable becomes `{}`, non-object (array) → 400 `{"error":"JSON body must be an object"}`. Verified live: `[1,2]` to `/fb_react` → 400.
- On signed agent routes (`/api/forum/react` etc.), musefm-v1 auth is checked BEFORE body parsing, so malformed JSON from an unauthed caller → 401 auth error, never a parser 500.
- No 500s observed on any malformed-JSON probe.

### 3. Missing params — CLEAN (one P2 below)
- `POST /api/identity/register {}` → 400 "bad handle (3-20 chars: letters, numbers, _)"; `{"handle":"qabot1"}` → 400 "bad public_key (need base64url Ed25519, 32 bytes)". Good sequential validation.
- `POST /api/link_muse {}` → 400 "code required"
- `POST /vote` empty form (anon) → 302 to `/login?next=/` (no 500)

### 4. Unauthenticated hits on auth paths — CLEAN
- `GET /mod/flags`, `/settings`, `/mod/uploads` → 302 to login (HTML pages)
- `GET /api/notifications`, `/api/openmic/mine` → 401 JSON `{"error":"musefm-v1 auth failed: missing action"}`
- `POST /mod/flags/1/resolve`, `/settings/link-code`, `/pet/adopt` (anon) → 302 to login; `POST /api/notifications/read` → 401. No action taken in any case.
- Web write routes (`/vote`, `/post/<pid>/comment`, `/fb_react`) enforce CSRF: wrong/missing token → 403 "bad form token — reload and try again". Note: the CSRF token is minted into the session on page render and the session cookie rotates at that point — a probe artifact, not an app bug.

### 5. Rapid repeat requests — CLEAN (design note P2)
- 10 rapid `GET /api/shorts` → all 200, no errors. (No read-path limiter; acceptable.)
- 10 rapid anon `POST /vote` → all 302 to login; 10 rapid anon `POST /fb_react` (JSON) → all 401. No 500s, no state corruption.
- `check_limit` buckets are keyed `(bucket, ip)` — per-IP, so anonymous traffic cannot burn another user's budget. Correct design.
- Rate limiter FIRED correctly: `/submit` returned 429 `{"error":"rate limit hit — slow down, friend"}` under this run's concurrent load (bucket "post", 5/hr per IP).
- **P2 note:** `_hits` is an in-memory dict per process. Under multi-worker gunicorn each worker gets its own bucket, so effective limits multiply by worker count and reset on every deploy/restart. Fine for abuse-throttling; not a hard guarantee.

### 6. Reaction-picker edge cases — CLEAN (validation exemplary)
Authenticated (qaprobe1) `POST /fb_react` JSON probes, all against `target_type=post, target_id=1`:
| input | result |
|---|---|
| `"like"` | 200 added / toggled off correctly |
| `"dislike"` | 400 "reaction must be one of: like, love, haha, wow, sad, angry" |
| `""` | 400, same message |
| 10,000-char string | 400, same message |
| `123` (number) | 400 "bad reaction: must be a string" |
| `target_id: 0 / -5 / 99999999999` | 400 "unknown target" |
| `target_type: "DROP TABLE"` | 400 "target_type must be one of: post, comment, episode, video, photo" |
| `"LIKE"`, `" like "` | normalized (strip().lower()) → toggle works |
| `{bad json` | 400 (unparseable → `{}`, validation catches it) |
- `fb_reactions.fb_react` validates reaction name first, then `validate_target`, all parameterized SQL. No injection surface.
- **P2:** the non-JSON form path of `/fb_react` catches ValueError and silently `redirect()`s with no error surfaced to the user — a bad reaction from a plain form POST gives zero feedback (same pattern as /vote below).

### 7. Share-link / ID formats — CLEAN
- No `/s/<id>` short-link route exists in app.py — all `/s/*` variants → 404.
- `sqlite_int` converter: `/video/-5`, `/video/99999999999999999999`, `/gif/0`, `/photo-file/-1`, `/c/general/post/abc`, `/watch/abc` → all 404, no tracebacks.
- URL-encoded SQLi (`/s/%27%20OR%201%3D1--`) → 404.
- Path traversal on `<path:fname>` routes: `/audio/<path:fname>` and `/episode-video/<path:fname>` both guard `if ".." in fname or "/" in fname: return "nope", 400`. Verified: `..%2F..%2Fapp.py` → 400 "nope"; literal `/audio/../../app.py` is normalized by the server to `/app.py` → 404 before the route sees it. No file disclosure.

### 8. Comment submission — CLEAN except 2× P2
- Empty body → 400 "comment body required"
- Comment on nonexistent post → HTML 404 page
- **Stored XSS: NOT vulnerable.** `<script>alert(1)</script>` comment renders as `&lt;script&gt;...` on `/c/lobby/post/1`; a script-tag post title (created by the concurrent human tester, post 8) renders escaped in `<title>` too. Jinja autoescape holding.
- **P2 — silent truncation:** a 200,000-char comment body was accepted (302) and stored truncated to exactly 2000 chars. If the cap is intentional it should be surfaced ("trimmed to 2000 chars"); if not, it's data loss. Recommend: reject or warn instead of silent trim.
- **P2 — double-submit duplicates:** two rapid identical `POST /post/1/comment` created two identical comment rows (ids 3, 4). No idempotency token / dedupe window, so double-clicking "comment" visibly duplicates. Same class of issue as the silent-302 vote behavior below.

### 9. Vote route — CLEAN except P2
- CSRF + session enforced; `db.vote` validates `target_type`, `value in (1,-1)`, target existence ("unknown target"), all parameterized.
- **P2 — errors swallowed into silent redirects:** the HTML form path wraps `db.vote` in `try/except (ValueError, TypeError)` and on ANY error does `redirect(_safe_next(data.get("next")))` → 302 to `/`. So `target_id=abc`, `target_id=99999999`, `value=999` all produce a silent 302 with zero user feedback. The JSON path correctly returns 400 with the message. Recommend mirroring the JSON 400 behavior (or a flashed error) on the form path.

### 10. Open redirects — CLEAN
- `_safe_next()` blocks absolute URLs, scheme-relative (`//evil.com`), backslashes, control chars. `POST /login` with `next=https://evil.example.com/steal` → 302 to `/`. `GET /login?next=//evil.com` → renders login page (next discarded). No open redirect found.

### 11. Method mismatches — CLEAN
- `GET /vote`, `GET /logout` → 405; `DELETE /api/shorts` → 405. Correct.
