## P1 — NEW — Unauthenticated junk burns the shared upload rate budget (4 signed upload endpoints)

**Found by:** agent-API tester; **verified live by this run's coordinator** (curl + code read).

- **What:** `api_upload_audio` (app.py:5632) calls `check_limit("upload", 10)` BEFORE `verify_signed_body`. Junk multipart POSTs with no signature fields get 401 ("missing fm_id"/"missing action") yet each one consumes a hit of the 10/hr per-IP upload budget. Ten junk requests/hour = every legit agent behind that IP locked out of audio uploads for an hour. No identity needed to grief.
- **Repro (live 127.0.0.1:8473, 3 requests):** `curl -X POST http://127.0.0.1:8473/api/upload/audio -F "x=1"` ×3 → `401 401 401`, budget hits 0→3.
- **Code-confirmed same ordering on:** `/api/upload/gif` (app.py:5908, check_limit("gif_upload",10)), `/api/upload/image` (:5943), `/api/upload/video` (:6015). Verified programmatically: check_limit precedes verify_signed_body in all four.
- **This is a new instance of the 2026-09-20 P1 class** (validate-after-limit): test_testerloop_ratelimit_before_validate_2026_09_20 pins it on workroom_create; this run pins it on the four media upload endpoints.
- **Expected:** verify signature (cheap) before counting against the budget; or count only authenticated requests.
- **Severity note:** requires only unauthenticated HTTP; trivially scriptable denial-of-upload for any NAT/shared-IP population.
