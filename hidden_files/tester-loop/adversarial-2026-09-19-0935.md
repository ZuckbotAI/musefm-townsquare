## Findings

### 1. (P1, KNOWN — corroborating evidence) Concurrent writes → unhandled 500 via sqlite lock
- Repro: any two overlapping signed writes, e.g. `POST /api/forum/vote` and
  `POST /api/forum/comment` issued in parallel (observed repeatedly 14:38:58–14:40:31).
- Exact response: HTTP 500, body `<!doctype html>...<title>500 Internal Server Error</title>...`
- Traceback (hidden_files/tester-loop/server.log, lines 195–234, 236–262, 459–485):
  `app.py:445 verify_signed_body → identity.py:196 db.note_nonce →
   db.py:1624 DELETE FROM seen_nonces → db.py:658 self.db.execute →
   sqlite3.OperationalError: database is locked`
- Expected: a 429/503 with retry guidance (or a busy-timeout/retry in `db._exec`),
  not an unhandled 500. Endpoints observed 500ing this way: `/api/forum/vote`,
  `/api/forum/comment`, `/fb_react` (web), `/api/upload/audio`.
- Caveat: observed under 3 parallel tester subagents on one SQLite DB; single-user
  sequential traffic did not reproduce it.

### 2. (P2) Rapid double-vote toggles the vote OFF — double-click = no vote
- Repro (signed, fm_vJ_I2FupeEbB, own post id 10):
  `POST /api/forum/vote {"target_id":10,"value":1}` → 200 `{"ok":true,"score":1}`;
  repeat identical request → 200 `{"ok":true,"score":0}` (vote removed);
  then `{"value":-1}` → 200 `{"ok":true,"score":-1}`.
- Expected (arguable): second identical vote is idempotent (stays +1). Current
  toggle semantics mean a rapid double-click / retried request silently un-votes.
  If toggle is intended, fine — but the brief asked about rapid clicking, and this
  is the one place where a repeat click inverts the user's intent.

### 3. (P2, question) `/api/forum/react` allows multiple different emojis per identity per post
- Repro: `POST /api/forum/react {"target_id":10,"emoji":"🔥"}` → 200 `{"reactions":{"🔥":1}}`;
  then `{"emoji":"❤️"}` → 200 `{"reactions":{"❤️":1,"🔥":1}}` — 2 reactions from 1 identity.
  Same-emoji repeat is idempotent (stays 1). By contrast `/api/forum/fb_react`
  enforces one-per-identity (toggle/switch: `{"action":"removed"...}`, `{"action":"switched"...}`).
- Inconsistent models between the two reaction systems. Possible Signal-farming
  angle: `/react` awards the author +2 per reactor ("never for self-reactions") —
  award dedupe key is `reaction:<target>:<reactor>` (not per-emoji), so likely only
  +2 once, but worth confirming in db.award.

### 4. (P2, open question) No visible body/title length caps; 500-char title untestable this run

  200 (id 7). Accepted without complaint.
- 500-char / 1000-char / emoji-flood / `<script>` titles could not be tested:
  `POST /api/forum/post` rate limit is 5/hour per IP (`check_limit("post", 5)`,
  app.py:1003/1817) and earlier posts in this run exhausted it → 429

- Comment XSS payload IS properly escaped in rendered HTML
