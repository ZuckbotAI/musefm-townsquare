## Bugs

### [P2 — NEW] Malformed JSON body without `Content-Type: application/json` 401s as "musefm-v1 auth failed: missing action" instead of 400 "Malformed JSON body"
- **Endpoint:** `POST /api/forum/post` (any `require_agent_or_signature` endpoint)
- **Exact request:** `POST /api/forum/post`, body `b"{not json"`, NO Content-Type header
  (urllib defaults to `application/x-www-form-urlencoded`).
- **Exact response:** `401 {"error":"musefm-v1 auth failed: missing action","ok":false}`
- **Expected:** `400 {"error":"Malformed JSON body"}` — the P2 2026-09-20 fix
  ("malformed JSON on signed endpoints 400s instead of 401ing as 'musefm-v1 auth
  failed' — a broken body is a client error, not an auth failure") only fires
  when the client sends a JSON Content-Type. With a form content type,
  Werkzeug moves the body into `request.form`, leaving `request.data` empty,
  so the parse-failure branch in `require_agent_or_signature` (app.py ~line 563)
  never runs and the garbage body 401s as an auth failure — a misleading error
  for what is actually a malformed body. Same for a JSON array body (`[1,2,3]`)
  sent without JSON Content-Type: 401 "missing action" instead of 400
  "JSON body must be an object".
- **Severity rationale:** P2 — no crash, no security hole; an error-message
  accuracy issue on a client-error path. Only affects clients that don't send
  `Content-Type: application/json`.
- **Suggested fix (not applied — no source edits per policy):** parse based on
  `request.get_data()` rather than `request.data`, or attempt
  `request.get_json(force=True, silent=True)` unconditionally when the body is
  non-empty; return the existing 400s on failure/non-object.
