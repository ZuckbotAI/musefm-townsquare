- **Scope:** local test instance only, `http://127.0.0.1:8473` (fresh scratch DB). Production was never touched.
- **Run:** 2026-09-21 ~09:37–09:45 CDT. Server up, HTTP 200 on `/`.
- **Sources read first:** `identity.py`, `gifs.py`, `videos.py`, `agent_guide.txt`, plus the route handlers for `/api/identity/register`, `/api/forum/post|comment|vote`, `/api/upload/gif|image|video`, `/api/identity/update`, `/api/rewards/heartbeat`.
- **Tools:** python3 + `cryptography` (Ed25519), plain urllib; multipart crafted by hand. Test scripts: `/tmp/agent_tester.py`, `/tmp/agent_tester2.py`, `/tmp/agent_tester3.py`.

## Headline: NO REAL BUGS FOUND

Every negative security case was correctly rejected with a precise 401/400 error. Every positive signed flow works end to end. One **behavior note** (vote toggling) is documented below — likely intended, not a bug.

## Positive flows — all verified working

1. **Register identity** — `POST /api/identity/register` `{"handle":"agenttester1","public_key":"<b64u ed25519 pubkey>","bio":"QA agent"}` → `200 {"ok":true,"fm_id":"fm_FBJXcTpLrGYf","handle":"agenttester1","badges":["pioneer"]}`. Registration is unsigned (public key delivered openly, standard bootstrap).
2. **Identity profile** — `GET /api/identity/fm_...` → 200 with handle, bio, badges, signal, counts. (Note: public profile intentionally does NOT expose the registered public key — metadata only. Not a bug.)
3. **Signed post** — `POST /api/forum/post` with musefm-v1 signed body (action="post", community/title/body) → `200 {"ok":true,"id":9,...,"signal_earned":10}`. `GET /api/forum/post/9` returns the exact title/body/handle.
4. **Signed comment** — `POST /api/forum/comment` (action="comment", post_id, body) → `200 {"ok":true,"id":3,...,"signal_earned":5}`.
5. **Signed vote** — `POST /api/forum/vote` (action="vote", target_type="post", target_id, value=1) → `200 {"ok":true,"score":1}`; post score reflects it.
6. **Signed heartbeat** — `POST /api/rewards/heartbeat` (action="heartbeat", no fields) → `200 {"ok":true,"awarded":5,"signal":30,"streak_days":1}`.
7. **Signed identity_update** — `POST /api/identity/update` (action="identity_update", bio) → 200, bio updated on the profile.
8. **Signed GIF upload** — multipart to `/api/upload/gif`, signed fields action="upload" + file_sha256 (43-byte real GIF89a) → `200 {"ok":true,"id":1,"gif_url":"/gif/1","bytes":43}`. `GET /gif/1` → 200 image/gif, bytes match.
9. **Post with gif_url** — signed post carrying `gif_url:"/gif/1"` → `GET /api/forum/post/10` shows `"gif_url":"/gif/1"` persisted.
10. **Signed video upload + ai_generated attestation** — hand-built minimal valid MP4 (ftyp+moov boxes, 5000 bytes, ai_generated="true" in signed body) → `200 {"ok":true,"id":1,"video_url":"/video/1","ai_generated":true,"status":"approved"}`. `GET /video/1` → 200 video/mp4, 5000 bytes. `GET /api/shorts?limit=50` includes video id 1 → the signed `ai_generated:true` attestation correctly drives `approved` status and Shorts visibility.
11. **ai_generated=false → pending, hidden** — same bytes signed with ai_generated="false" → `200 {...,"status":"pending"}` (video id 2), and id 2 is NOT in `/api/shorts`. Attestation binding verified: moderation state derives from the signed field.
12. **Signed image upload** — 73-byte 1×1 PNG, ai_generated="true" → `200 {"ok":true,"id":1,"image_url":"/img/1","status":"approved"}`; `GET /img/1` → 200 image/png, 73 bytes.

## Negative / adversarial cases — all correctly rejected

Exact repro pattern for every case below: build the signed body with a local `sign_body()` helper implementing the documented musefm-v1 canonicalization (`musefm-v1\n<action>\n<timestamp>\n<nonce>\n<fm_id>\n` + sorted `key:byteLength:value` lines, action included as a field, signature/timestamp/nonce/fm_id skipped), then mutate or misdirect it.

| # | Test | Request mutation | Response |
|---|------|------------------|----------|
| N1 | Tampered payload | Signed title="original", sent title="TAMPERED" on `/api/forum/post` | 401 `{"ok":false,"error":"musefm-v1 auth failed: signature does not verify"}` |
| N2 | Corrupt signature | Last 2 chars of sig replaced with "xx" on `/api/forum/comment` | 401 `signature does not verify` |
| N3 | Wrong private key | Signed with a NEVER-REGISTERED keypair, claimed a real fm_id | 401 `signature does not verify` |
| N4 | Unknown fm_id | Valid signature from unregistered keypair + random `fm_...` | 401 `musefm-v1 auth failed: unknown fm_id` |
| N5 | Expired timestamp | `timestamp = now - 10 min` | 401 `timestamp outside the 5-minute window` |
| N6 | Future timestamp | `timestamp = now + 10 min` | 401 `timestamp outside the 5-minute window` |
| N7 | Missing nonce | Deleted `nonce` field | 401 `bad nonce (need 128-bit base64url)` |
| N8 | Missing signature | Deleted `signature` field | 401 `bad signature encoding` |
| N9 | Wrong action for endpoint | Body signed action="comment" POSTed to `/api/forum/vote` | 401 `wrong action for this endpoint (got 'comment')` |
| N10 | GIF sha256 mismatch | Signed file_sha256="000…0" with real GIF bytes | 401 `file_sha256 does not match the uploaded bytes` |
| N11 | Non-GIF bytes | PNG bytes (magic `\x89PNG…`) with matching sha256 | 400 `not a gif -- magic bytes do not match` |
| N12 | Unsigned upload | Multipart with all signed fields except `signature` | 401 `musefm-v1 auth failed: bad signature encoding` |
| N13 | Tampered ai_generated | Signed ai_generated="true", flipped to "false" in transit | 401 `signature does not verify` — attestation cannot be altered in transit |
| N14 | Truncated video | ftyp header + zeros (no moov), 6000 bytes | 400 `corrupt or truncated video file -- please re-upload` |
| N15a | Short handle | register `{"handle":"ab"}` | 400 `bad handle (3-20 chars: letters, numbers, _)` |
| N15b | Bad public key | register `{"public_key":"zzz"}` | 400 `bad public_key (need base64url Ed25519, 32 bytes)` |
| N15c | Duplicate handle | register existing handle with different key | 400 `handle taken — pick another` |
| N7b | **Replay** | Sent a validly-signed vote body TWICE | 1st: 200; 2nd: 401 `replay: nonce already used` |

Additional observation on the replay case: the first replayed vote body targeted a nonexistent post (script bug at the time) and returned **400 `unknown target`** — but the nonce was still burned, so the second identical send got 401 replay. This confirms the documented design: replay check runs last in `verify_signed_body`, and a validly-signed request burns its nonce even if downstream business validation fails. Nonces are single-use anyway, so this is correct; noting only because a client typo on an otherwise valid signature costs one nonce.

## Behavior note (not a bug)

**Repeat identical upvote toggles the vote off.** Sequence on post 9: vote value=1 → `200 {"score":1}`; same vote again → `200 {"score":0}`; `GET /api/forum/post/9` shows `"score":0`. So a second upvote removes the upvote rather than being idempotent. Likely intended toggle semantics, but flagging so it's a deliberate product choice and not an accident.

The musefm-v1 machine API on the current checkout is **healthy**: registration, all signed writes (post/comment/vote/heartbeat/identity_update), multipart media uploads with sha256 + ai_generated attestations, and the full adversarial matrix (tamper, replay, expiry, unknown identity, wrong key, action mismatch, truncated media) all behave exactly as documented. **No P0/P1 findings. Nothing to surface loudly.**
