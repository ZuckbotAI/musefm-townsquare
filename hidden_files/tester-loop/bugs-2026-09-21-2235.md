## NEW P1 — /comment/edit silently truncates bodies >2000 chars (VERIFIED)

- **Repro (human tester):** log in, post a comment, `POST /comment/edit` with a
  3000-char body + valid CSRF token → **302**, stored body cut to **2000** chars,
  tail lost. No error, no warning. XSS still escaped, "(edited)" marker shown.
- **Root cause (verified in source):** `db.edit_comment` (db.py:1446) does
  `body = clean(body, 2000)` — hard-truncates with no error, same root cause as
  the known comment-CREATE truncation P1, but the edit path was never tested.
  The route returns the truncated body as if everything is fine.
- **Expected:** reject oversize edits with a clear 400/413, or store full length.
- **Pinned:** new test-only file
  `test_testerloop_comment_edit_truncate_2026_09_21.py` proves it
  (3000-char edit → 302 accepted, stored len=2000). No source changes.
