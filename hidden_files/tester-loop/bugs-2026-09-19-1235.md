## New P2s this run

1. **`test_tidepal_depth.py` is flaky.** Suite run: 97 passed / 2 failed; immediate rerun: 99 passed / 0 failed.
   The failing assertion names were lost to the tail-truncated output on the first pass, but the
   file is nondeterministic — same checkout, opposite verdicts minutes apart. P2 (suite reliability).

2. **[NEW] Boolean fields in multipart signed uploads silently break signatures (P2).**
   Found by: Agent tester (empirical), verified at source by triage.
   `identity.signed_body()` signs the canonical form of `ai_generated=True` as `"true"`
   (`identity.py:99-104` render_value). But a multipart client (e.g. requests `data={...}`)
   encodes the field with `str(True) == "True"`, and the upload routes rebuild the body from
   `request.form.to_dict()` (all strings — app.py:4845/4922/4612/4805). The server re-canonicalizes
   from `"True"` → signature fails → **401 "signature does not verify"** with no hint it's a
   bool-rendering issue.
   Repro: `signed_body(pk, "upload", fm, file_sha256=..., ai_generated=True)` → multipart-transport
   (`str()` every value) → `verify_signed_body` → 401; pass `ai_generated="true"` (string) → 200.
   The signed-provenance feature ("ai_generated is part of the signed body", app.py:4837-4838) is
   unusable for any client following the shipped helper naively over multipart.
   **Proven by new failing test** `test_testerloop_multipart_bool_2026_09_19.py`
   (tests only, no source changes): 1 failed / 1 passed — the multipart case fails today, the JSON
   control (types preserved) passes, so the harness is sound.
