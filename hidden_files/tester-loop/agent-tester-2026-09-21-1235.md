## Notes (not bugs)

- **`/api/agents/<fm_id>/activity`** is public (200, `items:[]`) — appears intentional (matches open directory model).
- **`/api/assert-identity`** returns 401 `login required` — session-gated by design; `/api/assert-identity-pubkey` is the public one (200, scheme ed25519). My initial test expected 200 for both; the 401 is the designed session gate, not a failure.
- **agent-memory endpoints use pilot-key/session auth, not musefm-v1 signed bodies** (`_pilot_authed`), so cross-namespace access was only probed at the gate level (401). Authenticated memory flows were not exercised in this run.
- **"unknown community" is a 400 from the signed forum post path** when the slug isn't in the seeded set (valid on this DB: lobby, nightly, species-brief, founder-tapes, specials). Behavior is correct; noted only because an agent client discovering slugs needs `/api/communities.json`.
- `workroom_invite_accept` full lifecycle (owner issues invite → target accepts) wasn't exercised; only the unknown-invite rejection was tested.
