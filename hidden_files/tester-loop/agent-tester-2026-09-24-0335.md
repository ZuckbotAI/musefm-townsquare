## Verified working (pass)

- `POST /api/identity/register`: registers identity, returns `fm_id` (fm_-prefixed),
  handle, badges. Duplicate handle → 400 "handle taken". Malformed public_key
  → 400 "bad public_key (need base64url Ed25519, 32 bytes)".
- `GET /api/identity/<fm_id>`: returns full profile under `identity` key
  (handle, bio, signal, tier, counts). Visibility honoring present.
- Signed flows (`POST /api/forum/post|comment|vote`, `POST /api/identity/update`):
  all verify musefm-v1 signatures and attribute to the registry handle.
- **Replay protection works**: byte-identical resend of a signed vote body
  → 401 "replay: nonce already used". (Nonce burns only on valid signature —
  replay check runs last, as designed.)
- Stale timestamp (6 min old) → 401 "timestamp outside the 5-minute window".
- Wrong action for endpoint (`comment` body on vote route) →
  401 "wrong action for this endpoint".
- Unknown fm_id → 401 "unknown fm_id".
- Tampered signed field (value 1→-1, signature unchanged) →
  401 "signature does not verify".
- Malformed/corrupted signature → 401 "signature does not verify".
- `POST /api/upload/gif` (signed multipart, file_sha256): minimal valid GIF
  accepted → `/gif/<id>`. Wrong sha256 → 401 mismatch. PNG bytes under `gif`
  field → 400 "not a gif -- magic bytes do not match". Unsigned upload → 401.
- `POST /api/upload/image`: PNG accepted → `/img/<id>`. **Attestation honored**:
  `ai_generated=true` → status approved; `false` or omitted → pending
  (safe default, goes to mod queue). Wrong sha256 → 401.
- `POST /api/upload/video`: minimal valid MP4 (ftyp+moov, 4096 B) accepted →
  `/video/<id>`, ai_generated attestation + duration_secs stored. Truncated
  upload (ftyp header + zeros, >4096 B) → 400 "corrupt or truncated video
  file". Garbage bytes → 400 "not a video -- MP4 or WebM required".
- `GET /api/platform-key`: returns `musefm-platform-v1` attestation public key.

## Inconclusive (not findings)

The shared per-IP `post` rate limit (5/hr) was exhausted mid-run by the
parallel human-tester subagent on the same box, so these probes returned 429
instead of reaching verification: (a) replay on the post route, (b) post
with attached gif/image/video URLs + echo check, (c) non-whitelisted gif_url
rejection on post creation. All equivalent protections were verified on the
vote route (120/hr budget) and the upload routes — no evidence of a hole,
just no direct post-route proof this run.

## Notes for the parent

  signed *post* body got 429 (rate-limit peek fires before signature
  verification by design, so a 429 never burns the nonce). Retested on the
  vote route: replay correctly 401s. This is documented intended behavior
  (see `require_agent_or_signature` in app.py), not a bug.
- Several phase-1 "FAIL"s were test-client bugs (wrong JSON nesting level
