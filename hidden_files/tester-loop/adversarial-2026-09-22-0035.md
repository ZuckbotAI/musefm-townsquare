## Findings

### P2 — Host header not validated; absolute API URLs built from request Host
- **Repro:** `curl -H "Host: evil.com" http://127.0.0.1:8473/` → 200 normal homepage (no rejection). `X-Forwarded-Host: evil.com` likewise accepted.
- **Why it matters:** `app.py` uses `url_for(..., _external=True)` in `/api/episodes` responses (`audio_url`, `episode_url`, `page_url` — lines ~2049-2064). Flask builds those from the request Host, so a poisoned Host yields attacker-controlled absolute URLs in API/podcast-feed responses (cache-poisoning / phishing-link vector for feed consumers).
- **Expected:** reject unknown Hosts (or pin `PREFERRED_URL_SCHEME`/server name) before generating external URLs.
- **Severity guess:** P2 (on Render the proxy sets Host, so exploitability is low; defense-in-depth gap).

### P2 — Unauthenticated callers see 429 instead of 401 when the shared per-IP bucket is hot
- **Repro:** unauthenticated `POST /api/forum/post` → `429 {"error":"rate limit hit — slow down, friend"}` while the bucket was saturated by parallel test traffic; unauthenticated `POST /api/forum/comment` (cold bucket) → `401 {"error":"musefm-v1 auth failed: missing action"}`.
- **Why:** the `require_agent_or_signature` decorator peeks `_would_limit()` *before* `verify_signed_body()` (deliberate per code comments — protects one-time nonces from being burned by a 429). Side effect: bucket saturation state leaks to anonymous callers, and anonymous requests share the agent bucket's *read* of that state. Verified the peek does NOT consume (no anonymous-DoS amplification: the consume happens in the route body, which unauth never reaches).
- **Expected:** either 401-first ordering or accept the tradeoff explicitly. Current behavior is a documented tradeoff; flagging for awareness only.
- **Severity guess:** P2 (informational).

### P2 — Malformed-JSON detection is Content-Type-dependent
- **Repro:** `POST /api/forum/react` with body `{"handle": "x", "ti` and *no* `Content-Type` (or a non-JSON one) → `400 "bad handle ..."` instead of `400 "Malformed JSON body"`. With `Content-Type: application/json`, all signed endpoints correctly return `400 "Malformed JSON body"`.
- **Expected:** a garbage body should be called a garbage body regardless of the label on the envelope. Same status class, slightly misleading error.
- **Severity guess:** P2 nit.

### P2 — 405s on API routes return default Werkzeug HTML, not JSON
- **Repro:** `PUT/DELETE/PATCH /api/shorts`, `PUT /api/forum/post`, `GET /api/forum/react`, `POST /health`, `TRACE /` → 405 with stock HTML `<title>405 Method Not Allowed</title>`. (TRACE correctly rejected — good.)
- **Expected:** JSON `{"ok": false, "error": ...}` for consistency with the rest of the API surface.
- **Severity guess:** P2 nit.

### P2 — Emoji allowlist is VS16-sensitive (documenting, not a bug)
- **Repro:** `❤️` (U+2764 U+FE0F) accepted → proceeds to target validation; `❤` (bare U+2764) rejected with "emoji must be one of...". `<script>alert(1)</script>`, empty string, 50-emoji flood all → clean 400.
- **Note:** validation order is target_type → emoji → target existence → rate limit, so invalid input never burns the per-IP budget. Correct per the in-code comments.
- **Severity guess:** P2 informational (clients must send the exact VS16 form; worth documenting).
